# 从本机导入用量信息

magpie 支持便携目录，所以本 App 带的是**第二份** magpie，它的账本从零开始。这个功能把
本机另一份 magpie（用户自己那份）的历史并进本 App 这一份，装上就能点。

## 入口在哪

magpie 工作区 → 设置 → **同步与备份** → 最下面一行「从本机导入用量信息」。

那一行不是 magpie 自己的，是本 App 的代理注入的（和主题下拉同一套办法）：

| 位置 | 东西 |
| --- | --- |
| `runtime/proxy.mjs` | `IMPORT_CSS` / `importBlock()`（样式）、`IMPORT_CLIENT`（客户端脚本，插到 `#syncList` 末尾）、端点 `POST /_hana/import-usage` |
| `runtime/import-usage.mjs` | 合并引擎：探测源目录、逐文件合并、备份、原子落盘 |

客户端脚本挂了一个 `MutationObserver`，因为 magpie 切标签页时会重画 `#syncList`，行被抹掉
就再插一次。按钮是两段式：第一下变成「确认导入（会重启 magpie）」，第二下才真跑，避免误触。

## 源目录怎么找（不能写死）

```
~/.config/magpie    %APPDATA%\magpie    %LOCALAPPDATA%\magpie    ~/.magpie
```

取第一个真的带 `usage.jsonl` 的；多个命中时取用量日志最新、最大的那份。本 App 自己那份
（便携目录）在候选之外，也会被显式跳过。

**必须用真实的用户环境来算这些路径**：这段代码跑在 App 的 runtime 子进程里，那里的
`os.homedir()` 不是用户真实的家目录（实测撞过：拿 `os.homedir()` 去找，一个候选都命不中）。
所以引擎收的是 `realUserEnv()` 给的那份环境，`APPDATA` / `LOCALAPPDATA` 缺失时从家目录推。

## 并什么、不并什么

并：`usage.jsonl`、`quota-history.json`、`credits-daily.json`、`affinity.json`、`served.json`、
`qoder-checkin.json`、`workbuddy-checkin.json`、`routing/`。

不并（状态、身份、凭据、设置跟着各自的安装走）：`install-id`、`stats-sent`、`last-version`、
`migrations.json`、`applied.json`、`library.json`、`plugins.json`、`plugins/`、`providers.json`、
`logins.json`、`plugin-*.json`、`cli-identity.json`、`settings.json`、`zcode-device-mid`、
`start-menu-shortcut`，以及 `import-backup/`、`icons/`、`cache/`。

## 幂等（这功能的命门）

| 文件 | 去重键 | 冲突时 |
| --- | --- | --- |
| `usage.jsonl` | `route_id`，没有则 `t+req+status+in+out` | 保留本 App 那条 |
| `quota-history.json` | 时间点 `at` | 保留本 App 那个点 |
| `routing/*.jsonl[.gz]` | 记录 `id` | 保留本 App 那条 |
| `credits-daily.json` | 按天，取两者较大的观测（同一份额度，窗口越全越大） | 取大 |
| `affinity.json` | 并集 | 本 App 优先 |
| `served.json` / 签到 | 取较晚的时间戳 | 较晚的 |

`affinity.json` 是粘性路由的缓存，magpie 自己会修剪它，所以它在两边都会变；并进来无害。
实测：并完再点一次，`usage.jsonl` 2888 行全被判为重复，新增 0 条。

## 安全与可回滚

- **源目录只读**，引擎里每个写入都过 `assertInside`，只允许写本 App 的家目录里面。
- 导入前先停 magpie：这些表它在内存里也存着一份，不停就白改；并完再起回来。客户端那行
  按钮的说明里写明了「会重启一次，正在跑的请求会中断」。
- 每次导入前把要改的文件整份备份到 `<家目录>/import-backup/<时间戳>/`，拷回去就是回滚。

## 自己验一遍

演练（只算不写、不重启，用来确认源目录找得到）：

```powershell
$port = (Get-Content "$env:USERPROFILE\.hanako\app-data\magpie-hana\runtime.json" -Raw | ConvertFrom-Json).proxyPort
$body = '{"apply":false}'
Invoke-RestMethod "http://127.0.0.1:$port/_hana/import-usage" -Method Post -ContentType "application/json" -Body $body |
  Select-Object ok, @{n='源';e={$_.report.source}}, @{n='新增';e={$_.report.added}}
```

真导入（会把 `apply` 换成 `true`）：

```powershell
Invoke-RestMethod "http://127.0.0.1:$port/_hana/import-usage" -Method Post -ContentType "application/json" -Body '{"apply":true}' |
  Select-Object ok, @{n='新增';e={$_.report.added}}, @{n='备份';e={$_.report.backup}}
```

界面那行要人看一眼：它只出现在「同步与备份」页，别的页不该有。

## 踩过的两个坑（都跟「别人电脑上也能用」有关）

1. **写进不存在的目录会失败**。手工合并那次目标里已经有 `routing/`，所以没暴露；换一个空
   目标立刻 `ENOENT`。现在 `writeAtomic` 先把父目录补齐 —— 拿一个空目录当目标跑一遍，是
   这个功能最该有的自测。
2. **候选路径不能拿 `os.homedir()` 算**。见上文「源目录怎么找」。
