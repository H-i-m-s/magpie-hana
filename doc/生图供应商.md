# 生图供应商（Hana 多媒体里的 magpie）

装好本 App，Hana 的「多媒体 → 图片生成」里就会出现一个叫 **magpie** 的供应商，
模型表跟着 magpie 网关里会画画的模型走。不需要配密钥、不需要装 MCP、不碰 `~/.config/magpie`。

## 三个文件各管什么

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | `capabilities` 里的 `app/media.provide`；`contributes.providers` 声明静态身份：`id=magpie-hana`、`displayName=magpie`、`authType=none`、`media.imageGeneration.models: []`（留空，真实模型运行期发现）。形状照抄 Hana 内置的 `jimeng-cli`。 |
| `media/provider.mjs` | 能力来源（模型表）+ 适配器（`submit` / `query` / `checkAuth`）。注册走 `ctx.media.registerCapabilitySource` / `registerAdapter`。 |
| `runtime/proxy.mjs` | 新增内部端点 `POST /_hana/draw`：整个生图来回（网关 + 下载厂商的图 + 落盘）都在这个进程里跑。 |

## 模型表从哪来

```
GET http://127.0.0.1:3425/v1/models        Header: X-Magpie-Drawers: 1
```

带这个头，magpie 才列出「会画画的模型」（`kind === "image"`）。这个头本来是 magpie 给
「另一个 magpie」准备的（源码 `internal/provider/remote_magpie.go` 的 `DrawersHeader`），
我们用同一个口子。当前实测只有 1 条：`workbuddy/hunyuan-image-v3.0-art`。

`refresh()` 返回的信封必须满足宿主两条硬校验，否则整个能力来源被拒：

- `media.imageGeneration.defaultModelId` 必须出现在 `models` 里；
- 每个模型必须带 `protocolId`（App 声明的 provider 不像 user/local 那样可以省）。

## 为什么下载放在代理进程里（别改回去）

App 的 `ctx.network.fetch` 只放行清单 `network.allowedHosts` 里列过的主机，而本清单里
只有 `127.0.0.1`。magpie 的出图接口把厂商的图以 **URL** 交回来（WorkBuddy 给的是腾讯云
CDN 上一条带签名的链接），适配器自己去下就死在这一步：

```
生图失败：Plugin network.fetch host "ai-corpus-backup-1258344699.cos.ap-beijing.myqcloud.com"
is not declared in manifest network.allowedHosts
```

把各家 CDN 写进清单等于白名单跟着厂商变，每加一个还要用户重新审一次（新增网络主机
会进审批）。所以改成本 App 自己的代理进程跑整个来回：那个进程是 App 申请来的 runtime
（`network: "external"`），也是 magpie 的父进程，本来就整棵树连着外网。适配器只跟自家的
`127.0.0.1` 说话，清单一个字都不用改。

顺带两个好处：几 MB 的图不必再经 JSON 过一遍宿主的门（那条路还受清单 8MiB 响应上限
约束）；下载先落本次任务自己的暂存目录，下完再 `rename` 进成品目录，宿主在成品目录里
扫新文件时不会看见半张图。

## 已知边界

- **`ratio` / `resolution` 这条通道不认**。magpie 的图片请求只吃 `size`（像素或 `auto`），
  比例由厂商定。适配器遇到这两个参数会记一条 warn 并按厂商默认出图，不假装做到了。
  所以适配器也不声明 `ratios` / `resolutions` 能力，免得给出兑现不了的选项。
- **必须点名模型**。WorkBuddy 的图花的是套餐积分，magpie 只在模型被点名时才用它
  （`internal/gateway/draw.go` 的 `AutoDrawer` 显式跳过 WorkBuddy）。`submit` 缺 `model`
  直接报错，不替它挑。
- **参考图最多 4 张**（magpie 一次最多 4 张）。适配器会把参考图读成 data URL 再传，
  因为网关只认 URL 或 data URL，不认本地路径。
- **magpie 没跑时** `refresh()` 会抛错，供应商显示为不可用；这不是静默给个空表。
- **一次最长 5 分钟**（magpie 的 `drawTimeout`）。所以 `submit` 立刻回 `taskId`、后台干活、
  `query` 轮询，和内置的即梦 CLI 应用同一套形状。

## 自己验一遍

代理端口每次重载都会变，先从运行时文件里读：

```powershell
$port = (Get-Content "$env:USERPROFILE\.hanako\app-data\magpie-hana\runtime.json" -Raw | ConvertFrom-Json).proxyPort
Invoke-RestMethod "http://127.0.0.1:$port/_hana/status" | Select-Object phase, upstreamPort, magpiePid
```

看到 `phase = ready` 就说明代理和 magpie 都起来了。再确认供应商注册没注册：

```powershell
Select-String -LiteralPath (Get-ChildItem "$env:USERPROFILE\.hanako\logs" -Filter *.log |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName `
  -Pattern "生图供应商已注册|adapter registered: magpie-hana-images" | Select-Object -Last 2
```

真出一张图（**会花 WorkBuddy 积分**，一次一张）：

```powershell
$body = @{
  model  = "workbuddy/hunyuan-image-v3.0-art"
  prompt = "一只橘猫坐在窗台上，午后暖光，简约插画"
  n      = 1
  outDir = "$env:TEMP\magpie-draw-test"
} | ConvertTo-Json
Invoke-RestMethod "http://127.0.0.1:$port/_hana/draw" -Method Post -ContentType "application/json" -Body $body
```

回 `{ ok = $true; files = @("magpie-….png") }` 就是通了；出错时 `error` 里是 magpie 或厂商
的原话，不是兜底文案。
